# EvoLink

面向 Emby / Jellyfin / Plex 的 **strm 媒体库 + 归档刮削 + 权重洗板** 一体化工具。
不存真实影片文件，只存片名 / 封面 / 发行时间，以及指向网盘资源的 `.strm` 链接。

纯 Python 标准库实现（零第三方依赖），单个容器即可运行。

---

## 功能

| 模块 | 做什么 |
|---|---|
| **115 → 302 换链** | strm 里写 115 路径，播放时由 EvoLink 换链成带鉴权的直链做 302 跳转。Emby / Jellyfin / Plex 三套反代各自独立 |
| **链接同步库** | 扫描本地 strm 目录，与 Emby 实际库比对，产出「有 / 无 / 失效」清单，支持批量清理与回收站 |
| **归档刮削** | 按 TMDB 信息生成规范命名的 strm，目录层级按分类规则生成，可试跑预览再落盘 |
| **权重洗板** | 同一作品有多个版本（4K REMUX / 1080p WEB-DL…）时按 13 个维度打分，只留最优版本。方案可新建 / 编辑 / 导入 / 导出 JSON |
| **分类设置** | 定义归档目录的层级规则：媒体类型 → 二级分类 → 三级及以下子目录。带模板、字段字典、条件说明 |
| **删除联动** | Emby 里删除条目时，自动联动清理对应 strm（webhook） |
| **缺口比对** | 拉取 TMDB / 榜单，与现有库存比对，找缺失的片 |

## 快速开始

```bash
docker compose up -d
```

启动后打开 `http://<你的NAS地址>:9191`。

首次使用按这个顺序配置：

1. **设置页** → 填 Emby 地址与 API Key、TMDB Key、115 Cookie
2. **归档刮削** → 填源目录 / 输出目录 / 命名模板 → 点「生成计划（试跑，不写盘）」看结果 → 确认后「执行写入 strm」
3. **分类设置** → 「从模板选择」挑一套起点，再按自己的习惯增删改条件与顺序 → 保存
4. **权重洗板** → 新建方案 → 调各维度权重 → 保存 → 回到归档页选为「电影 / 剧集洗板方案」

## 归档目录结构

归档路径按「一级 → 二级 → 三级」三级生成：

```
电影 / 国产电影 / 阿凡达系列 / 阿凡达：水之道 (2009).strm
```

- **一级**：媒体类型（电影 / 剧集），可在「分类设置」里关掉
- **二级**：分类规则命中项。规则**从上到下依次匹配，第一条命中的生效**，所以更具体的放前面，兜底规则放最后
- **三级及以下**：子目录。可由「演员 / 导演 / 系列关键词」自动生成，也可手工添加

二级规则可用的匹配条件（每个都有说明）：

| 条件 | 说明 |
|---|---|
| TMDB 类型 ID | 逗号分隔，负号 = 排除。如 `99,-10402` 表示纪录片但排除音乐纪录片 |
| TMDB 类型名 | 中文名，如 `动作、喜剧、科幻` |
| 国家/地区代码 | 如 `CN、US、JP` |
| 地区中文名 | 如 `大陆、日本、美国` |
| 原始语言代码 | 如 `zh、en、ja` |
| 年份区间 | 如 `2020-2099`，也支持 `2020-` / `-2019` |
| 标题关键词 | 片名包含任意一个即命中 |
| 系列关键词 | **只用于生成「XX系列」子目录，不参与是否命中** |
| 演员 / 导演 | **只用于生成「演员名 / 导演名」子目录，不参与是否命中** |

## 权重洗板

同一作品有多个版本时，逐维度打分再求和，总分最高者胜出。

13 个维度：分辨率、音频编码、视频编码、色深、帧率、杜比视界、动态范围、片源、字幕、文件扩展名、特效、发行组、自定义属性。

每个维度内部还能配「黑名单 / 白名单」。归档时如果选了洗板方案，同一部作品只保留得分最高的那个版本；`每部保留版本数` 改成 2 就是最优的两个都留。

方案可以**另存为 JSON 导入 / 导出**，方便在不同机器间迁移。

## 302 换链

strm 文件里只写一行路径，播放时才换链：

```
http://<EvoLink地址>:9191/api/swap115/<115路径>
```

EvoLink 读出路径 → 用配置的 Cookie 签发直链 → 302 跳转。签发与取链必须同一个 UA，程序已处理。

反向代理端口在「115 → 302 换链」子页配置：

| 端口 | 用途 |
|---|---|
| 9191 | EvoLink 管理界面 |
| 8093 | Emby 302 反代入口（上游是原生 Emby） |
| 8099 | Jellyfin 302 反代入口（上游是原生 Jellyfin） |
| 32411 | Plex 302 反代入口（上游是原生 Plex） |

> ⚠️ 宿主机的原生 Emby / Jellyfin / Plex 端口由各自容器占用，**EvoLink 不要占用也不要改动**。

## 挂载说明

| 挂载 | 用途 | 读写 |
|---|---|---|
| `data/` | 配置与数据库 | 读写 |
| `app/web/index.html`、`app/server.py`、`app/core/*.py` | 源码（改完重启即生效） | 只读 |
| `/vol1/1000/Link:/Link` | strm 库，反代读首行换链 | 只读 |
| 同上 → `/app/Link` | 链接同步、strm 生成器的写入目标 | 读写 |
| Jellyfin `config/data` | 反代查条目 → strm 路径 | 只读 |
| Plex `config` | 同上 | 只读 |
| Emby `data` | 删除联动按 Path 反查条目 ID | 只读 |
| `/vol1/1000/CloudNAS:/CloudNAS` | 115 网盘本地挂载（CD2） | 只读 |

> 容器用 `network_mode: host`，所以 `ports:` 映射全部失效，服务直接绑宿主机端口。端口要改请在网页设置里改。

## 常见问题

**换链 401 / 403**：115 Cookie 过期或 UA 不一致。在设置页重新扫码登录。

**反代能起来但播放器放不了**：多半是 strm 目录没挂对，或容器读不到 `/Link` 下的文件。检查 compose 里的挂载路径。

**归档生成的文件名不对**：先在「分类设置」里调条件，再去归档页「生成计划（试跑）」预览，最后才写入。

**删了 Emby 条目但 strm 还在**：Emby 侧要先手动加一次 webhook 通知（指向 EvoLink 的 `/api/emby/webhook`），并在「删除联动」页保存 Token。

**扫描整个网盘太慢**：扫描支持两种模式。优先用「本地模式」遍历 CD2 挂载目录，零网盘请求；只有需要看网盘完整目录树时才用「接口模式」。
