## 〇、先说清楚三件事

**1. 这不是「再推一个面板」，而是换一个品类。**

| | Docker-Link | EvoLink-CN |
|---|---|---|
| 目标用户 | NAS / Docker 玩家 | 已经有媒体库、且**库管理乱了**的人 |
| 用户痛点 | 面板难用 / 想要国产替代 | 库里有重复、有缺失、命名混乱、链接点不开 |
| 需求紧迫性 | 中（工具类，收藏即用） | **高（痛点明确，付钱意愿更强）** |
| 传播性 | 一般（面板截图同质化） | 强（「我发现我的库少了 3000 部」天然有传播力） |

**2. 国内版与国际版不要投同一个平台。**

国际版（`Evolink`）投 Reddit / HN / Docker Hub / Awesome 列表；
国内版（本仓库）投什么值得买 / linux.do / 恩山 / NodeSeek / 阮一峰周刊。
**同一平台发两个仓库的稿子会被当成重复营销。**

**3. 本方案是零预算版。** 第七章列出了明确**不采用**的付费渠道。

## 四、核心打法：三个项目互推

这是 EvoLink 与 Docker-Link 最大的不同。**单独推 EvoLink 是浪费**，三个项目构成一条完整链路：

```
Docker-Link（运维容器） → EvoLink（治理媒体库） → Playable（播放）
```

### 4.1 三个仓库互相引用（已落地）

每个项目的 README 都有一节 **Ecosystem**，列出另外两个并说明如何配合；每个项目都带一份
同结构的 `docs/ECOSYSTEM.md`。用户点进任意一个仓库，都能顺着链接走完整条链路。

**为什么有效**：单项目推广的转化瓶颈是「用户不知道它能解决什么」；三项目互推把「一个工具」
变成「一套方案」，认知成本大幅下降，同时每个项目的 star 都在为另外两个导流。

### 4.2 内容打法：一篇文章讲三个项目

| 文章角度 | 主推 | 顺带 |
|---|---|---|
| 「我的 NAS 媒体库终于不乱了」 | EvoLink | Docker-Link（怎么部署监控）、Playable（怎么在电视上看） |
| 「从 Portainer 到自建面板再到媒体库治理」 | 三项目同框 | 全串 |
| 「一个 4K 电视柜需要哪几个自建服务」 | Playable | EvoLink（喂片源）、Docker-Link（跑起来） |

这种「三合一」文章在**什么值得买和掘金**效果好（读者要完整方案）；
在技术社区要逐站改写，不要一稿通投。

### 4.3 联合 Release / 互链公告

- 三个仓库互相加「相关项目」说明，形成闭环
- 三项目同一时间发 Release，在各自 Release notes 里写「本次可以和 X 配合使用」
- 阮一峰周刊 / HelloGitHub 一次只能推一个项目，**优先推 EvoLink**（痛点最强），
  稿件里带上另外两个的链接（注意外链数量上限）

## 五、各平台红线与可用话术

### 5.1 什么值得买（¥0）

**红线**
- ❌ 谢绝个人业务推广、销量推广 → 必须写成「我自己 NAS 上用下来的真实体验」
- ❌ 禁微信、电话、二维码
- ⚠️ 每篇最多 **3 个外链**
- ⚠️ 图片 3–6 张实拍图，无水印、无二维码；头图建议 710×300
- ⚠️ 正文约 1500 字，配图 ≥4 张

**可用话术**
> 标题：`NAS 媒体库体检实录：Emby 库里少了 3000 多部，赔了我一个周末`
> 结构：我的环境 → 库为什么乱了（重复、命名不统一、缺失）→ 工具怎么用（索引 → 比对 → 洗板 → 归档）→ 界面实拍 → 部署命令 → 缺点（免费版功能有限）→ 项目地址
> 结尾：`我的机器是 X，自建家用，商用请自行评估。`

### 5.2 linux.do（¥0）

- ❌ 禁 AFF / 联盟链接
- ❌ 禁引流到其他社区或社群（**三项目互推要写成「同作者的另外两个项目」，不要写成导流**）
- TL0 用户：单帖 ≤2 链接、≤1 图
- 建议打「开源分享」标签

### 5.3 恩山（¥0）

- ❌ 未经同意不得发任何商业广告 → 写成技术分享
- ❌ 禁 QQ/微信群、二维码
- 飞牛用户最关心 Docker 部署细节，**compose 要完整贴出**并标明必填挂载

### 5.4 NodeSeek（¥0）

- 推广区发帖 ≤3 次/周；同内容勿重复发
- 禁推广代理类（EvoLink 是自建工具，不涉代理，天然安全）
- 技术细节给足，用户吃「实测数据 + 踩坑记录」这一套
